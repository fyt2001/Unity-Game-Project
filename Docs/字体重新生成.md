# 中文 SDF 字体重新生成（AlibabaPuHuiTiSDF.asset）

`Assets/Game/Resources/Fonts/AlibabaPuHuiTiSDF.asset` 约 24 MB。它不进 git，也不用 LFS。新 clone 下来没有这个文件时，按下面的步骤在本机重新烘焙。
步骤依据的是 `Assets/Game/Editor/FontTools/` 下的源码：`TMPFontBaker.cs` 和 `UIFontCharsetCollector.cs`，核对日期 2026-11-13。如果源码改了，以源码为准。

## 入库情况
| 文件 | 是否入库 | 用途 |
|---|---|---|
| `Assets/Game/Fonts/AlibabaPuHuiTi-3-55-Regular.ttf`（+.meta） | 已入库 | 烘焙用的源字体（`TMPFontBaker.kSourceTtf`） |
| `Assets/Game/Fonts/Generated/charset_extra.txt` | 已入库 | 人工维护的补充字符表，工具不会覆盖它 |
| `Assets/Game/Fonts/Generated/charset.txt`、`charset_project_only.txt` | 已入库 | 烘焙输入，可以重新扫描生成 |
| `Assets/Game/Resources/Fonts/AlibabaPuHuiTiSDF.asset` | **未入库** | 烘焙产物，`CJKFont.lua` 通过 `Resources` 路径 `Fonts/AlibabaPuHuiTiSDF` 加载 |
| `Assets/Game/Resources/Fonts/AlibabaPuHuiTiSDF.asset.meta` | **未入库** | 里面的 guid 被 prefab 和 TMP Settings 引用，见下文“GUID” |
| `_FontSource/CJK.ttf`（+.meta） | **未入库（缺口）** | 已入库的 `EntryLegalSDF.asset` 的源字体，不是本页烘焙用的源 |

## 步骤（Unity 编辑器，菜单都在 `Tools/字体/` 下）
1. 可选：执行 `Tools/字体/1. 扫描 UI 字符集`（`UIFontCharsetCollector.Scan`）。
   - 它会扫描所有 prefab 里的 TMP 文本（包括 inactive 节点）、场景 YAML 里的文本字段，以及 Lua/C# 里的字符串字面量。
   - 结果写到 `Assets/Game/Fonts/Generated/charset_scanned.txt`，再和 `charset_extra.txt` 合并成 `charset.txt`。
   - 不扫描的目录：TextMesh Pro Examples/Fonts、ThirdParty、Spine、StreamingAssets、LuaScripts/XLua、Fonts/Generated。
   - 仓库里已经有 `charset.txt`，所以这一步可以跳过。
2. 执行 `Tools/字体/2. 烘焙 TMP 静态字体（主集）`（`TMPFontBaker.BakeFull`）。
   - 输入：`Assets/Game/Fonts/Generated/charset.txt`。
   - 源字体：`Assets/Game/Fonts/AlibabaPuHuiTi-3-55-Regular.ttf`。
   - 参数写死在源码里：pointSize 48、padding 3、图集 1024×1024、`GlyphRenderMode.SDFAA`、开启多图集。先用 Dynamic 模式 `TryAddCharacters`，再切成 `AtlasPopulationMode.Static` 保存。
   - 输出：`Assets/Game/Resources/Fonts/AlibabaPuHuiTiSDF.asset`。Console 里会打印 `[TMPFontBaker] 烘焙完成`，包括字形数、图集页数和缺字。
3. 执行 `Tools/字体/4. 校验已落盘字体资产`（`TMPFontBaker.Verify`），确认 `HasCharacter` 为 N/N、缺字为“无”，并且 `atlasTextures`、`material` 都不是 `<null>`。
4. 可选：执行 `Tools/字体/3. 烘焙 TMP 静态字体（精简集）`，输入 `charset_project_only.txt`，输出 `AlibabaPuHuiTiSDF_Lite.asset`。工程运行时不用它。
5. 运行时排查缺字：Play 时由 MissingGlyphWatcher 记录，之后执行 `Tools/字体/5. 汇总运行时缺字记录` 查看。

## GUID（必须处理，否则引用会断）
27 个 UI prefab、`Assets/TextMesh Pro/Resources/TMP Settings.asset`（默认字体和 fallback）以及 `EntryLegalSDF.asset` 都通过 guid 引用这个字体：

```
guid: e9306f1132efaa54694f3cf7bfbc9cc8
```

- `TMPFontBaker` 只有在 `.asset.meta` 已经存在时才会保留原 guid。新 clone 里没有这个 .meta，烘焙后会生成新的 guid，上面这些引用就会失效。
- 处理方法：烘焙完成后先**关闭 Unity**，把 `AlibabaPuHuiTiSDF.asset.meta` 里的 `guid:` 行改成上面的值，再打开工程。
- 不要在 Unity 开着的时候改。也不要先单独放一个 .meta 再启动，Unity 会把没有对应资产的 .meta 删掉。
- 更省事的办法：只把这个约 170 字节的 `.meta` 入库，大的 `.asset` 仍不入库。这需要用户另外决定，当前没有入库。

## 已知缺口
- `_FontSource/CJK.ttf` 没有入库。它是 `EntryLegalSDF.asset` 的源字体（按 `Docs/多平台适配评估.md`，已从 Assets 移出）。
  - `EntryLegalSDF.asset` 本身已入库，可以直接使用。
  - 但新 clone 里没法给它补字或重新烘焙，也说不清它当初的确切烘焙参数（本仓库没有对应的烘焙菜单）。需要的话，要从原作者机器上取回 CJK.ttf。
- 重新烘焙出来的字体和原文件不一定逐字节相同，取决于 TMP 版本和字符集，但功能上等价。
